## 三、对接 checklist

### 3.1 成员2（用户端）对接

参考文档：
- `reference-member2/docs/协议对齐备忘.md`（客户端协议假设）
- `docs/协议冻结说明.md`（服务端权威版本）

**已确认冻结的约定**：
1. ✅ 传输层：4字节大端长度头 + UTF-8 JSON
2. ✅ 消息外壳：`{action, requestId, data}` / `{requestId, code, message, data}`
3. ✅ 错误码：采纳客户端提出的全部错误码（见协议冻结说明）
4. ✅ 用户身份识别：**连接绑定userId**方式（无token）
   - `user.login` 成功后将 userId 绑定到该 TCP 连接
   - 后续订单操作按连接归属识别用户
   - 未登录连接执行订单操作返回 `1003`
5. ✅ 桩状态枚举：0=空闲、1=充电中、2=故障、3=离线
6. ✅ 桩类型枚举：0=快充、1=慢充
7. ✅ 订单状态：字符串枚举 `RESERVED → CHARGING → WAIT_SETTLEMENT → FINISHED`
8. ✅ 距离计算：由**服务端**计算并排序（`station.nearby`）

**待联调的action**（按优先级）：
1. `user.login`（Commit 3）：手机号登录/自动注册
2. `user.profile.update`（Commit 3）：昵称/头像修改
3. `user.recharge`（Commit 3）：充值
4. `station.nearby`（Commit 4）：附近站点（服务端计算距离）
5. `station.detail`（Commit 4）：站点详情+桩列表
6. `order.active`（Commit 5）：查询未完成订单
7. `order.reserve`（Commit 5）：预约充电桩
8. `order.start`（Commit 5）：开始充电
9. `order.status`（Commit 5）：充电中实时数据
10. `order.stop`（Commit 5）：停止充电（幂等）
11. `order.settle`（Commit 5）：结算扣款
12. `order.history`（Commit 5）：订单历史

**头像方案**：客户端提议使用 data-URL（`data:image/<fmt>;base64,<data>`），
服务端将采纳此方案，限制大小 ≤ 256KB。

### 3.3 成员4（机器学习）对接

参考文档：
- `reference-member4/DATA_DICTIONARY.md`（数据字典）
- `docs/协议冻结说明.md`（ML数据接口定义）

**数据契约**（Commit 7）：

**方式一：SQLite数据库导出**（推荐）
- 提供完整的 `ev.db` 或数据库副本
- 包含 `users`、`stations`、`chargers`、`orders` 表
- 订单表必须包含：`orderId, userId, stationId, chargerId, startTime, endTime, duration, energyKwh, amount, status`

**方式二：HTTP接口查询**（备选）
- `ml.orders.export`：导出历史订单（支持时间范围、站点筛选）
- `ml.stations.info`：站点与桩基础信息
- `ml.predict.submit`：接收预测结果（JSON格式）

**核心字段要求**：
1. ✅ 订单表：
   - `status` 只有 `'FINISHED'` 的订单计入统计
   - `startTime` / `endTime`：epoch毫秒时间戳
   - `energyKwh`：充电量（预测核心目标）
   - `amount`：金额（元，精确到分）
2. ✅ 站点表：
   - `totalChargers`：充电桩总数（用于计算空闲桩）
3. ✅ 时间对齐：小时粒度，按整点聚合

**预测结果接入**：
- JSON格式（见 `DATA_DICTIONARY.md` 第五节）
- 包含 `stationId`, `forecasts` 数组（1h/6h/24h horizon）
- 字段：`predictedLoad`, `predictedActiveChargers`, `peakTime`, `peakLoad`

## 四、数据库表设计（Commit 1）

见 `docs/协议冻结说明.md` 第八节，核心表：

1. **users**：手机号唯一，包含 nickname/avatar/balance/status
2. **admins**：admin 账号密码
3. **stations**：name/address/latitude/longitude/pricePerKwh
4. **chargers**：属于 station，包含 code/type/status/powerKw
5. **orders**：关联 user 和 charger，完整时间/电量/金额字段

**状态字段与枚举对应**：
- `chargers.status`：0=空闲、1=充电中、2=故障、3=离线
- `chargers.type`：0=快充、1=慢充
- `orders.status`：`'RESERVED'`, `'CHARGING'`, `'WAIT_SETTLEMENT'`, `'FINISHED'`
- `users.status`：0=正常、1=冻结

## 六、联调建议

### 6.1 网络层联调（现在可用）

```bash
# 启动服务端（Linux虚拟机）
./server/build/ev-server --host 0.0.0.0 --port 9000 --database ./ev.db

# 冒烟测试（验证framing正确性）
./server/build/ev-smoke-test 127.0.0.1 9000

# 手动测试PING（任意TCP客户端）
echo -n '{"action":"PING","requestId":"test-1","data":{}}' | \
  awk '{printf "%c%c%c%c%s", 0,0,0,length($0),$0}' | \
  nc 127.0.0.1 9000 | xxd
```

### 6.2 业务接口联调（Commit 3+）

**建议顺序**：
1. 先用 `PING` 确认连接稳定
2. 测试 `user.login`（手机号登录/注册）
3. 测试资料修改、充值（确认余额持久化）
4. 测试站点查询（确认距离排序）
5. 测试完整充电流程（预约→开始→停止→结算）
6. 跨端验收（用户充电→管理员看到状态变化→ML获取数据）

### 6.3 问题反馈

联调中遇到问题请：
1. 记录完整的 `requestId`、`action`、请求/响应 JSON
2. 查看服务端日志（会输出 requestId 和关键实体 id）
3. 确认数据库状态（`sqlite3 ev.db "SELECT * FROM ..."`）
4. 在项目仓库开 issue 或直接找成员1
