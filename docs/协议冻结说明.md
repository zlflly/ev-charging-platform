## 1. 传输层约定（已冻结）

### 1.1 帧格式

```
+----------------+------------------+
| Length (4字节) | Payload (变长)   |
| 大端整数       | UTF-8 JSON       |
+----------------+------------------+
```

- **长度字段**：4 字节，大端序（Big-Endian），**不包含**自身的 4 字节
- **Payload**：UTF-8 编码的 JSON 对象
- **最大 Payload**：16 MB（16777216 字节）
- **超长处理**：服务端拒绝连接，客户端断开重连

### 1.2 粘包/半包处理

- **服务端**：使用 `FrameCodec` 循环解码，一次 `readyRead` 可能包含多帧
- **客户端**：参考 `reference-member2/user-client/src/net/TcpClient.cpp`

## 2. 消息外壳（已冻结）

### 2.1 请求格式

```json
{
  "action": "user.login",
  "requestId": "req-1234",
  "data": { ... }
}
```

- `action`：业务动作字符串（见下文 action 列表）
- `requestId`：客户端生成的唯一标识（UUID/雪花ID/时间戳），用于响应匹配
- `data`：业务数据对象（可为空对象 `{}`）

### 2.2 响应格式

```json
{
  "requestId": "req-1234",
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

- `requestId`：与请求中的 `requestId` 相同
- `code`：错误码（0 表示成功，见下文错误码表）
- `message`：错误描述（成功时为 "ok"）
- `data`：业务数据对象（失败时可为空对象 `{}`）

## 3. 错误码（已冻结）

| 错误码 | 常量名 | 含义 | 客户端处理 |
|-------|--------|------|-----------|
| 0 | `CodeOk` | 成功 | 正常处理 data |
| 1001 | `CodeBadRequest` | 参数格式错误 | 弹窗提示 message |
| 1002 | `CodeUserFrozen` | 账号被冻结 | 强制登出，提示联系管理员 |
| 1003 | `CodeNotLoggedIn` | 未登录 | 跳转登录页 |
| 1101 | `CodeAdminAuthFailed` | 管理员账号或密码错误 | 提示"账号或密码错误" |
| 2001 | `CodeChargerUnavailable` | 桩不可用/被占用 | 提示用户选择其他桩 |
| 2002 | `CodeBalanceInsufficient` | 余额不足 | 提示充值 |
| 2003 | `CodeOrderConflict` | 订单状态冲突 | 提示刷新订单状态 |
| 5000 | `CodeServerError` | 服务端内部错误 | 提示"服务器繁忙，请稍后重试" |

**扩展规则**：
- 1xxx：通用业务错误
- 2xxx：充电业务错误
- 5xxx：服务端内部错误

## 4. 枚举定义（已冻结）

### 4.1 充电桩状态（数据库存储整数）

| 整数值 | 枚举名 | 含义 | 前端展示 |
|-------|--------|------|---------|
| 0 | `ChargerStatusIdle` | 空闲 | "可用" |
| 1 | `ChargerStatusCharging` | 充电中 | "使用中" |
| 2 | `ChargerStatusFault` | 故障 | "故障" |
| 3 | `ChargerStatusOffline` | 离线 | "离线" |

**协议字段名**：`status`（整数）

### 4.2 充电桩类型（数据库存储整数）

| 整数值 | 枚举名 | 含义 | 功率范围 |
|-------|--------|------|---------|
| 0 | `ChargerTypeFast` | 快充 | 60-120 kW |
| 1 | `ChargerTypeSlow` | 慢充 | 7-22 kW |

**协议字段名**：`type`（整数）

### 4.3 用户状态（数据库存储整数）

| 整数值 | 枚举名 | 含义 |
|-------|--------|------|
| 0 | `UserStatusNormal` | 正常 |
| 1 | `UserStatusFrozen` | 冻结 |

**协议字段名**：`status`（整数）

### 4.4 订单状态（数据库存储字符串）

| 字符串值 | 含义 | 状态机流转 |
|---------|------|-----------|
| `RESERVED` | 已预约 | 初始状态 |
| `CHARGING` | 充电中 | `RESERVED` → `CHARGING`（插枪启动） |
| `WAIT_SETTLEMENT` | 等待结算 | `CHARGING` → `WAIT_SETTLEMENT`（拔枪停止） |
| `FINISHED` | 已完成 | `WAIT_SETTLEMENT` → `FINISHED`（用户确认结算） |

**协议字段名**：`status`（字符串）

**状态机规则**：
- 服务端是唯一状态机
- 客户端不允许自行修改订单状态，只能调用对应 action 触发状态转换
- 非法转换返回 `CodeOrderConflict`


```json
{
```
```json
  "orderId": 12345,
```

```json
  "reservedAt": "2026-09-04T10:00:00Z"
```

**业务规则**：
- 检查桩状态：必须为 0（空闲）

- 失败场景：桩不可用（`CodeChargerUnavailable`）、已有活跃订单（`CodeOrderConflict`）

## 7. 机器学习数据接口（Commit 7 补齐）

### 7.1 ml.orders.export（导出历史订单）

**用途**：为机器学习模型提供训练数据

**请求 data**:
```json
{
  "startDate": "2026-01-01",
  "endDate": "2026-09-04",
  "format": "json"
}
```

**响应 data**:
```json
{
  "orders": [
    {
      "orderId": 12345,
      "userId": 123,
      "stationId": 1,
      "chargerId": 101,
      "chargerType": 0,
      "power": 120.0,
      "reservedAt": "2026-09-04T10:00:00Z",
      "startedAt": "2026-09-04T10:05:00Z",
      "stoppedAt": "2026-09-04T11:00:00Z",
      "duration": 55,
      "totalKwh": 18.5,
      "totalCost": 27.75,
      "status": "FINISHED"
    }
  ],
  "count": 1,
  "startDate": "2026-01-01",
  "endDate": "2026-09-04",
  "exportedAt": "2026-09-04T12:00:00Z"
}
```

**业务规则**：
- 只导出 `status='FINISHED'` 的订单（对应机器学习端期望的 `completed`）
- `chargerType` 返回整数（0=快充、1=慢充），机器学习端可映射为字符串
- `duration` 返回充电时长（分钟）
- 时间范围最大 1 年
- 无需登录（供成员4直接访问）

**字段映射**：
- 数据库 `createdAt` → 响应 `reservedAt`（预约时间）
- 数据库 `startTime` → 响应 `startedAt`（开始充电时间）
- 数据库 `stopTime` → 响应 `stoppedAt`（停止充电时间）
- 数据库 `energyKwh` → 响应 `totalKwh`
- 数据库 `amount` → 响应 `totalCost`

### 8.4 chargers（充电桩表）

```sql
CREATE TABLE chargers (
    charger_id INTEGER PRIMARY KEY AUTOINCREMENT,
    station_id INTEGER NOT NULL,
    charger_code TEXT NOT NULL,
    type INTEGER NOT NULL,  -- 0=快充, 1=慢充
    power REAL NOT NULL,
```

---

### 8.5 orders（订单表）

```sql
CREATE TABLE orders (
    order_id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    charger_id INTEGER NOT NULL,
    status TEXT NOT NULL,  -- RESERVED/CHARGING/WAIT_SETTLEMENT/FINISHED
    reserved_at TEXT NOT NULL,
    started_at TEXT,
    stopped_at TEXT,
    settled_at TEXT,
    total_kwh REAL DEFAULT 0.0,
    total_cost REAL DEFAULT 0.0,
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    FOREIGN KEY (charger_id) REFERENCES chargers(charger_id)
);
```

**索引**：

## 9. 对齐结论与统一方案

### 9.1 订单状态命名冲突

**问题**：
- 用户端协议（已实现）：`RESERVED` / `CHARGING` / `WAIT_SETTLEMENT` / `FINISHED`
- 机器学习端期望：`completed` / `cancelled` / `pending`

**统一方案**：
- 数据库存储：使用用户端的四态字符串（与协议一致）
- 机器学习查询：WHERE `status='FINISHED'` 等价于 `completed`
- `cancelled` 状态当前协议未涉及，作为扩展状态保留
- 数据导出接口：直接返回数据库原值，机器学习端自行映射

### 9.2 充电桩类型/状态存储格式

**问题**：
- 协议（已冻结）：整数 0/1/2/3
- 机器学习端文档：字符串 `fast/slow`、`available/occupied/fault`

**统一方案**：
- 数据库存储：整数（与协议一致，节省空间）
- 前端展示：客户端自行映射为本地化文本
- 机器学习导出接口：返回整数，机器学习端可选映射为字符串

**映射表**：
```
类型：0 → "fast", 1 → "slow"
状态：0 → "available", 1 → "occupied", 2 → "fault", 3 → "offline"
```

### 9.4 身份识别方式

**统一方案**（已对齐成员 2/3）：
